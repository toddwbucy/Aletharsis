# V2 consumer alignment and outstanding acceptance

This maps the backend contract to the frontend PRD's §9 requirements. It does not implement a viewer, select a component or freeze the future F0 Occurrence schema.

- **Import identity:** `reportimport.Read` computes `ReportArtifactSHA256` over exact received bytes and retains an independent copy. Source identity is separately reported by `file.sha256`. Neither hash authenticates authorship or proves that an imported report's claimed source exists.
- **Finding identity:** use the computed report-artifact hash plus `finding_ref`, keeping the rule `id` and current array index as origin metadata. Filtered reports retain finding references; a reference is local to its exact report artifact, not a global UUID.
- **Text anchors:** `text` locator spans carry explicit scalar and original-byte ranges. Keep all disjoint spans. The initial mapping method points to a retained segment boundary table; source verification remains a separate operation. A navigation mapping is not edit authority.
- **Digest semantics:** the backend's `selected_text_sha256` with `digest_domain=aletharsis.text-selection/1` is a domain-separated composite digest over ordered span selections. It is **not** SHA-256 of concatenated UTF-8 text. The PRD's provisional raw-selection digest cannot be populated by copying this value. F0 must adopt the domain-tagged composite identity or name/store a separately computed raw digest explicitly. Span boundaries remain part of occurrence identity.
- **Presentation coordinates:** source Unicode scalars and bytes are authoritative. JavaScript UTF-16 boundaries are a derived display index; emoji surrogate interiors and synthetic reveal-marker interiors require an explicit boundary policy. Neither line numbers nor normalized presentation strings provide inverse source offsets.
- **Non-text evidence:** preserve structural-object, credential and sample locators in their declared variants. Whole-sample statistical evidence does not create exact watermark spans or a deletion target. Unsupported mappings/variants stay inspectable without guessed edit ranges.
- **Legacy evidence:** retain original 1.0 bytes and unknown coverage. A legacy parser failure without a code has an adapter diagnostic rather than an inferred cause. Do not add fields to the retained report.
- **Coverage:** keep capabilities, participation, availability, executions, exclusions and substantive results distinct. A filtered finding view cannot rewrite detector results. Disabled/unavailable declarations are neither negative results nor findings. Profiles/review state do not belong in original detector evidence.

`TestNativeReportConsumerCoordinates` exercises actual native emission, production import, independent source-byte/UTF-16 boundary expectations, selection identity and retained-byte isolation using BOM, supplementary emoji, combining marks, invisible formatting and bidi controls. Existing import tests cover all eight synthetic v2 fixtures and 37 legacy reports. This is backend consumer evidence, not completion of LOC-01–04 or the browser spike.

Remaining acceptance includes resolution of the measured resource limits, review of the F0 digest naming decision in its technical design, supported-platform CI and third-party review/merge. Schema 1.0 remains the default; no default-switch approval is inferred from opt-in emission.
